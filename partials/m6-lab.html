Lab 5: Test Pipeline on Gitee Go

Automate your pytest suite in a Gitee Go pipeline. Watch it go red, then green.

This lab uses the tested project from Lab 4 (board.py, tictactoe.py, and your test_board.py). You'll put pytest behind an automated pipeline that runs on every push.

1 · Confirm the tests pass locally

From the project root, make sure the suite is green before automating it — the pipeline can only run what already works on your machine:

pytest

If pytest isn't found, install it with pip install pytest (see Module 1). It's good practice to record the dependency so the pipeline installs the same thing — create a requirements.txt with one line:

# requirements.txt
pytest

2 · Create the Gitee Go pipeline

Enable Gitee Go on your repo (the Services tab), create a pipeline from the Python template, and replace it with the file below — Gitee stores it under .workflow/ in your repo. It installs pytest, runs the tests, then publishes a versioned release (see Class 11 for a key-by-key explanation):

# .workflow/master-pipeline.yml
version: '1.0'
name: master-pipeline
displayName: TicTacToe
triggers:
  trigger: auto
  push:
    branches:
      include:
        - master
stages:
  - name: test
    displayName: Test
    strategy: naturally
    trigger: auto
    steps:
      - step: build@python            # Python environment
        name: run_tests
        displayName: Run pytest
        pythonVersion: '3.12'
        commands:
          - pip install pytest        # or: pip install -r requirements.txt
          - pytest
  - name: release                     # runs only if test is green
    displayName: Publish
    strategy: naturally
    trigger: auto
    steps:
      - step: publish@release_artifacts
        name: publish_release_artifacts
        displayName: Publish
        version: 1.0.0.0
        autoIncrement: true

The exact step type and field names come from Gitee Go's template editor and can change; keep the shape (a test stage that installs pytest and runs it, then a release stage) and map it onto the current interface.

3 · Make it go red, then green

  1. Commit and push the .workflow/ file (and requirements.txt), then watch the pipeline turn green.
  2. Deliberately break a test (e.g. change an expected winner) and push: watch it turn red and read the failing assertion in the logs.
  3. Fix it and push again → green.
  4. (Optional) Add a pull_request trigger so a Pull Request can't merge while tests fail.
Done when

Every push to your repository automatically runs pytest on Gitee Go, you have seen a full red → green cycle, and a passing run on master publishes a versioned release.
