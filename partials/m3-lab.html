Prerequisites: two clones of your project

  1. Create two folders on your desktop: Repo1 and Repo2.
  2. Open a Git Bash window in each.
  3. Clone your Tic-Tac-Toe repository into both folders.
  4. Navigate each Git Bash window into its clone. Repo1 and Repo2 act as two different teammates sharing one remote.

Activity A: The accidentally-committed build artifact

Scenario

You are working with a teammate. While building the game you produced a compiled artifact, ttt.exe, in your workspace that should never be committed (an anonymous professor deducts 2.5 points for committed build artifacts). You have already pushed it to the remote, and only then created a .gitignore. You push everything, but the artifact is still on the remote, and your teammate has already pulled it. Now you must both fix your repositories.

Steps to reproduce the problem

  1. In Repo1, create a file ttt.exe (a stand-in for a compiled binary: just make a small file with this exact name).
  2. In Repo1, add, commit, and push ttt.exe.
  3. In Repo1, create a .gitignore file with an entry that ignores ttt.exe. (Ensure the file's extension really is .gitignore, not .txt: enable "show file extensions.")
  4. In Repo1, add, commit, and push the .gitignore.
  5. In Repo2, pull from the remote. (Repo2 now also has the unwanted artifact.)
Desired end state
  • Both workspaces still have ttt.exe on disk.
  • Both workspaces have a .gitignore ignoring it.
  • The remote has the .gitignore (with the entry) but contains no build artifact.

How to resolve: your task

Step 1 is given as an example. Add as many steps as necessary to reach the desired end state. For each step, describe the action clearly, record the Git command(s) used, and explain why you are doing it. If a step has no Git command, write N/A; if it uses several, put them on one line separated by |.
