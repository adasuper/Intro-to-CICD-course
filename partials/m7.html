Module 7 · Capstone · Classes 13–16

Final Project

In teams, extend the game through the full workflow you've learned: from issue to released, tested code.

Everything so far has built the machinery: version control, a clean repo, branches, automated tests, and a CI/CD pipeline. Now you put it to work. In teams of 2–3, add one feature to Tic-Tac-Toe and take it through the complete professional loop.

Schedule

Class 13Discussion & planning. Form teams, choose a feature, open issues on Gitee, assign owners, plan branches, agree on "done."
Classes 14–15Implementation. Issue-driven development: branch per issue → code + a unit test → push → PR → CI gate → review → merge.
Class 16Integration & demo. Final merge to master, tag a v1.0 release, and present.

Choose a feature

EasyRandom-move AI

A single-player mode where the computer plays a random legal move.

HardUnbeatable AI (minimax)

An opponent that never loses, and is very testable ("must take a winning move," "must never lose").

MediumN×N board

Generalise the board and win logic to larger sizes / Connect-Four style.

MediumScore & replay

A persistent high-score file and a play-again loop with difficulty levels.

Definition of done

  • The feature works and is merged into master via a Pull Request.
  • It has at least one meaningful unit test for any new logic.
  • CI (Gitee Go) is green on master.
  • The work is traceable: issues linked to PRs.
  • A v1.0 release is tagged on Gitee.

Demo

Each team shows: the green pipeline, the issue→PR history, the tagged release, and the feature played live. Close with a one-minute reflection on what branching and CI saved you.
