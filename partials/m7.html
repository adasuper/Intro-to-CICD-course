Follow Git Flow

Professional teams don't commit straight to the main line; they follow a branching model. The most common is Git Flow: two long-lived branches (main and develop) plus short-lived feature, release, and hotfix branches that each have one job. For this project, develop your feature using this flow.

Each branch has one job:

  • main: always-releasable history; here it's your repo's default branch (master on Gitee).
  • develop: the integration branch where finished features come together.
  • feature/<name>: one per issue, branched off develop and merged back via a Pull Request once CI is green. This is where your team's work happens.
  • release/*: a stabilising branch cut from develop when you're ready to ship; merges into main and back into develop.
  • hotfix/*: an urgent fix branched off main and merged back into both main and develop.
Do this

Develop your feature on a feature/<name> branch off develop, open a PR back into develop once the pipeline is green, and keep master for integrated, releasable code. Never commit straight to master.

Definition of done

  • The feature works and is merged into master via a Pull Request.
  • It has at least one meaningful unit test for any new logic.
  • CI (Gitee Go) is green on master.
  • The work is traceable: issues linked to PRs.
