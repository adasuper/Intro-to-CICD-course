Setup Lab: Get Your Machine Ready

Install and verify the full toolchain. Nothing later works until this does, so finish every checkpoint.

Goal

By the end of this lab you have a working C++ toolchain, a Gitee account with SSH access, and you have successfully pushed a small program to a Gitee repository.

Before you start

Work through the steps in order: each builds on the last. Instructions focus on Windows (most common here) with short notes for macOS and Linux. Every tool has an official download link plus a China mirror in case the official one is slow.

1 · Install Git

Git is the version-control tool at the centre of the course. On Windows the installer also gives you Git Bash: the terminal you'll use throughout.

⇣ Git for Windows All platforms
Windows
  1. Download and run the installer from the link above.
  2. Accept the default option on every screen: the defaults are correct for this course. Keep "Git from the command line and also from 3rd-party software" selected.
  3. Finish, then open Git Bash from the Start menu.
Official download slow? Get Git for Windows from the Tsinghua mirror: mirrors.tuna.tsinghua.edu.cn/github-release/git-for-windows/git/
macOS / Linux

macOS: Git arrives with the Xcode Command Line Tools (Step 2). Linux: sudo apt install git on Debian/Ubuntu.

Then set your identity once, in any terminal:

git --version
git config --global user.name "Your Name"
git config --global user.email "you@example.com"

2 · Install a C++ compiler (g++)

You need the GCC / g++ compiler. On Windows, pick one of the two options below: Option A is the simplest for beginners.

Windows · Option A: WinLibs (easiest: download & unzip)
⇣ winlibs.com
  1. On WinLibs, under the newest release download the UCRT runtime · Win64 · Zip archive (the "GCC + MinGW-w64 (UCRT)" build).
  2. Extract the zip to C:\mingw64: you should end up with a C:\mingw64\bin folder.
  3. Add C:\mingw64\bin to your PATH: press Win+R, run sysdm.cpl → Advanced → Environment Variables → select Path → Edit → New → paste the folder → OK.
  4. Close and reopen Git Bash so the new PATH takes effect.
Windows · Option B: MSYS2 (a full toolchain manager)
⇣ msys2.org
  1. Download and run the installer; keep the default location C:\msys64.
  2. When it finishes, open "MSYS2 UCRT64" from the Start menu.
  3. Update the package database: run this, let the window close if asked, reopen it and run again until it reports "nothing to do": 
    pacman -Syu
  4. Install the compiler toolchain (press Enter to accept all packages): 
    pacman -S --needed base-devel mingw-w64-ucrt-x86_64-toolchain
  5. Add C:\msys64\ucrt64\bin to your Windows PATH (same steps as Option A), then reopen Git Bash.
In China, set MSYS2 to a domestic mirror first: it is far faster. Follow the Tsinghua guide at mirrors.tuna.tsinghua.edu.cn/help/msys2/: add the tuna Server = lines to the top of the mirrorlist.* files in C:\msys64\etc\pacman.d\, then run pacman -Syu.
macOS / Linux

macOS: xcode-select --install (installs clang/g++ and git). Linux: sudo apt install build-essential.

Verify in a fresh terminal:

g++ --version

3 · Make (your build tool)

Make is the build system used from Module 5 onward. You do not need a separate download: it ships with the compiler toolchain you just installed.

Windows

Both compiler options from Step 2 ship the tool as mingw32-make.exe, inside the same bin folder you already added to your PATH. To be able to type plain make (as this course does), copy that file to make.exe in the same folder:

  • Option A (WinLibs): copy C:\mingw64\bin\mingw32-make.exe → C:\mingw64\bin\make.exe
  • Option B (MSYS2): copy C:\msys64\ucrt64\bin\mingw32-make.exe → C:\msys64\ucrt64\bin\make.exe

(Just copy and rename, keeping the original mingw32-make.exe in place. Then reopen Git Bash so it picks up the new name.)

macOS / Linux

macOS: make comes with the Xcode command-line tools from Step 2. Linux: it is part of build-essential.

Verify:

make --version

VS Code is the editor. Install it, then add two Microsoft extensions from inside VS Code.

⇣ code.visualstudio.com
  1. Download and install VS Code for your operating system.
  2. Open VS Code → click the Extensions icon in the left bar (or press Ctrl+Shift+X).

5 · Create a Gitee account & SSH key

Gitee hosts your repositories and runs the CI pipeline. To push your commits up to Gitee, your computer has to prove who it is every time it connects. There are two ways to do that, HTTPS and SSH, and it is worth understanding the difference before you set one up.

HTTPS vs. SSH: two ways to authenticate

Both transport the exact same Git data; they only differ in how the server checks that the connection is allowed.

HTTPSSSH
Remote URL looks likehttps://gitee.com/user/repo.gitgit@gitee.com:user/repo.git
How you prove it's youUsername + password / access token, typed (or cached) on each push.A cryptographic key pair stored once on your machine, no password typed.
Setup effortNone up front, but you re-enter credentials (or manage a token) repeatedly.A few minutes once; after that, pushing is friction-free.
Best whenOne-off clones, machines you don't control, networks that block SSH.Your own daily-driver machine, which is our case.

We use SSH in this course: you set it up once and never type a password to push again.

How SSH keys work

SSH uses a matched key pair: a private key that stays secret on your computer, and a public key you give to Gitee. When you connect, Gitee challenges your machine to prove it holds the matching private key, without the private key ever leaving your computer. The public key is safe to share; the private key (the file without .pub) must never be copied or posted anywhere.

↗ Register on gitee.com
  1. Create and verify an account at gitee.com.
  2. In Git Bash, generate a key pair (press Enter at every prompt to accept the defaults): 
    ssh-keygen -t ed25519 -C "you@example.com"

    Breaking the command down:

    • ssh-keygen: the program that creates a new SSH key pair.
    • -t ed25519: the key type (algorithm). Ed25519 is the modern, fast, secure default.
    • -C "you@example.com": a comment label attached to the key so you can recognise it later in Gitee's list. It does not have to be a real email; it's just a tag.

    This writes two files into ~/.ssh/: id_ed25519 (your private key, keep secret) and id_ed25519.pub (your public key, safe to share). The prompts ask where to save it (Enter = default) and for an optional passphrase that encrypts the private key on disk.

  3. Display and copy the public key: note the .pub extension; never copy the other file: 
    cat ~/.ssh/id_ed25519.pub

    cat prints a file's contents to the screen. Select the whole line it outputs (it starts with ssh-ed25519 and ends with your comment) and copy it.

  4. On Gitee: avatar → Settings → SSH Public Keys → Add Public Key → paste it and save. This tells Gitee to trust any machine that holds the matching private key.
  5. Test the connection: 
    ssh -T git@gitee.com

    ssh opens a secure connection; -T skips requesting an interactive terminal (Gitee doesn't offer a shell, only Git); git@gitee.com is the user git on the host gitee.com. A successful run greets you by your username: that confirms your key is recognised.

First-connection prompt

The first time you run ssh -T, you'll see "The authenticity of host 'gitee.com' can't be established… continue connecting (yes/no)?", type yes. This records Gitee's fingerprint so future connections are trusted automatically.

"Does not provide shell access" is success

A correct test prints something like "Hi user(@user)! You've successfully authenticated, but GITEE.COM does not provide shell access." That is not an error. The first half means your key worked and Gitee knows who you are. The second half is normal: the git account exists only to handle push/pull, not to give you a command prompt, so it logs you out instead of opening a shell (which is why we pass -T). A real failure looks different: Permission denied (publickey).

6 · Smoke test (the checkpoint)

Prove the whole toolchain works end-to-end. First, pick a folder to work in and create the file you'll compile.

  1. Choose a home for your project: somewhere easy to find, not inside a synced folder like OneDrive or Desktop. A path with no spaces or non-English characters avoids headaches later. For example: 
    # create the folder and move into it
mkdir -p ~/dev/hello
cd ~/dev/hello

    mkdir -p ~/dev/hello makes a dev/hello folder in your home directory (-p creates parents as needed and won't complain if it already exists); cd moves your terminal into that folder, so every command after this runs there.

  2. Create hello.cpp in this folder. Either run the echo command in the block below, or, if you prefer, open the folder in VS Code (code .) and create hello.cpp by hand with the same contents.
  3. Create the remote repository on Gitee so you have somewhere to push to. On gitee.com: + (top-right) → New Repository. Set Repository name to hello, and, importantly, leave it empty: do not tick "Initialize this repository", and don't add a README, .gitignore, or licence. An empty repo lets your local commits push cleanly without conflicts. Click Create.
This folder is your workspace

The folder you just made is your local workspace: the actual files on your disk that you edit and compile. When you run git init below, Git starts tracking changes inside this folder. How a file moves from your workspace all the way to Gitee (workspace → staging → local repo → remote) is the core of the next class, so don't worry about the git commands' details yet: just run them and watch it work.

Now run the full sequence from inside that folder:

# compile and run a hello program
echo '#include <iostream>
int main(){ std::cout << "toolchain OK\n"; }' > hello.cpp
g++ hello.cpp -o hello
./hello

# version it and push to a new empty Gitee repo
git init
git add hello.cpp
git commit -m "first commit: hello"
git remote add origin git@gitee.com:<your-user>/hello.git
git push -u origin master

Replace <your-user> (brackets and all) with your Gitee username: the handle from the "Hi user(@user)!" message in the SSH test. Easiest of all: open the new repo on Gitee → green Clone button → SSH tab → copy the exact git@gitee.com:… URL and paste it in place of the one above.

Done when

You can run ./hello, and hello.cpp appears in your repository on the Gitee website.
